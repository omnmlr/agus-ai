## Order of integration

1. Authenticate, upload a build, enroll the runner, and prove tenant separation, checksum and lease handling.
2. Execute the fixed wallet fixture, verify chain outcomes and compare it with a bounded agent attempt. Keep the original Android evidence accessible as a reproducible baseline.
3. Connect web, Android, CLI and MCP to the same API. Make unavailable capabilities, pending payments and rejected actions explicit.
4. Deploy to a separate HTTPS origin and database. Use a dedicated provider host and obtain disposable wallet funding through an authorized channel.
5. Exercise the signed financial APK with a disposable identity and record its original callback and reconciliation results. Keep instrumentation in the new repository or a separately approved target build.

Seeker hardware acceptance, SAS, comparisons across more agents, approved trajectory export and performance benchmarks follow the secure execution and settlement gates. [Implementation ledger](PROGRESS.md)
