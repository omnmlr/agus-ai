Start with a private, synthetic development environment. Each increment has an executable acceptance boundary. Keep new scopes disabled by default and leave the legacy device/runner path operational.

## Measurable release acceptance

Use these initial engineering targets, validate against hardware and adjust in versioned policy. A missing test result keeps the affected device/runtime/build ineligible.

- **Per-image compatibility.** Run emulator regression in CI and on at least a stock Pixel-class device, a supported high-volume non-Google OEM with its current shipping Android, and genuine Seeker for Seeker-only claims. Repeat onboarding and teardown on every supported OS/OEM policy change. Verify enrollment fails clearly and never alters an existing work profile.
- **Scope and isolation.** All mandatory negative cases in [the threat matrix](security.md) pass with positive controls, including both directions of bridges. Test at least two signed publishers and a wrong signer when allowing partner builds. Confirm that a work-profile install cannot update a personal build. Local Stop must work without ADB, root, device owner, Accessibility, personal app visibility or an external scheduler.
- **Stop and liveness.** For a cooperating foreground first-party workload, require cessation of new actions before the next step, observable reclaim within two seconds for the local UI path in every qualification case, and no resumed actions after Home, lock, reboot, aged offline TTL or revoke. Exercise at least 30 stop/recovery scenarios per configuration, including pending install. Report worst stop latency and any pending cleanup. Record local stop independently of a deferred server acknowledgment. Start with candidate 15-second heartbeat and 45-second hard local authority TTL and measure failure behavior.
- **Cleanup.** Run at least 30 alternating A/B fixture resets per image, including mid-task kill, offline, owner stop, earlier failed install and interrupted cleanup. Check package uninstall, data/grants/evidence/wallet residues and restored personal launcher. Require zero unexpected residue. Missing acknowledgement or failed postcondition inhibits assignment. Require fresh setup and qualification after profile deletion.
- **Power and time.** Use instrumented foreground windows on real charging devices before any overnight permission. Verify stop on stricter configured thermal/power ceilings, disconnect, task budget, owner interaction and actual wall duration. Log measurement age and OEM availability. Emulator observations have synthetic power and thermal provenance.
- **Independent evidence and provenance.** Enforce resource and tenant grants on every route and object. Verify tamper, replay, signature algorithm substitution, wrong signer, expired challenge, stale fence, reused chain signature and scope mismatch. Report provenance, exact build variant and rubric before comparisons.
- **Distribution, privacy and data.** Obtain permission for the selected DPC and APK delivery route, owner-facing disclosures and admin role. Exercise deletion, buyer export rights, rollback, and consent withdrawal with redaction and retention. Report reviewer disagreement with denominator before using reliability scores for pay or eligibility.

## Unknowns and dependency labels

| Status | Scope |
| --- | --- |
| Proven on the supplied baseline | Dedicated Android 15 AVD, bounded agent action path, Localnet independent verification, signed runner evidence, private and marketplace claim/cleanup. [Passing dedicated CI](https://github.com/omnmlr/agus-ai/actions/runs/45923508742) |
| Proven only as recorded in Phase 1 | See [the experiment](experiments.md) for exact image, observers, native actions, limitations and output. |
| Plausible and unverified | Multi-publisher authenticated SDK, effective default-deny profile network policy, lifecycle-safe coordination after installer transitions, robust stop for every app state, native runtime-to-lease and signed evidence upload, multi-customer cleanup and profile collision controls. |
| Needs physical hardware | OEM enrollment, coexistence with enterprise profiles, home/profile-pause behavior, actual thermal, charging and battery, attestation integrity levels, wallet UI and genuine Seeker/Seed Vault. |
| Requires elevated Android privileges | Dedicated runner’s local ADB and UI Automator, device-owner kiosk/secondary-user management, root/debug-shell helpers and some AVF capabilities. Managed-profile ownership is a separate user-approved scoped role. |
| Requires approval or credentials | Selected app-store DPC and package delivery, Play Integrity, production hosting and app distribution bindings, live model use if commissioned, funded disposable wallets and any future commercial treasury. |
| Unsuitable for personal pilot | Arbitrary binaries, remote ADB, root/shell helpers, unrestricted Accessibility, recording personal or protected apps, bypassing Android consent, and personal wallet journeys. |
| Deferred | Overnight unattended participation, app-window capture, wider Android image matrix, concurrent personal use, background virtualization, real-money settlement and commercial launch. |
