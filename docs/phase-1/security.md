# Security model and acceptance fixtures

The owner delegates authority for one approved workload in a profile they can remove. The personal user, work-profile apps, AGUS DPC/runtime, developer, agent planner, API/settlement and evidence reviewers are distinct trust principals. Android system and OEM controls underpin local user isolation. A device’s report is an authenticated claim. Independent checks are required for buyer assertions such as finalized settlement or hardware provenance.

## Threats, requirements and test cases

Each production-gate case uses synthetic data on a clean emulator and consenting dedicated qualification hardware before real personal-device eligibility. Record image, OS patch, OEM, role, exact policy/fixture version, positive control, abort path and cleanup. The Phase 1 lab covers only cases named in [the run evidence](experiments.md).

| Threat or boundary | Required control and acceptance signal |
| --- | --- |
| Personal contacts, photos, files, app data and account credentials | AGUS requests no personal content, usage, contacts, storage, notification listener or Accessibility grants. Seed separate parent/work synthetic contacts, media, files, app-private preferences, account and provider records. Test both ordinary app reads and authorized-looking Android chooser/docs/contact/URI routes from the work side, including malicious URIs and no implicit grants. Parent reads its own positive controls. Work sees only its own approved synthetics. Test any granted work-only permission and interaction with share journeys. |
| Wallet and protected credentials | Wallets, accounts and service principals are disposable and profile scoped. Use exact test cluster and independent RPC verification. Seed parent test wallet/account and verify no discovery/access/approval, including exported/deep-link routes. Test work-wallet intent resolution in both directions, explicit owner interaction and opaque secure windows. Keep funding actor, test payer and payout recipient separate. Evaluate real Seed Vault on genuine attended hardware. |
| Cross-profile clipboard, files, intents and OEM surfaces | Minimal DPC policy with zero AGUS bridge and deny-by-default authorized target allowlist. Test directional clipboard, keyboard clipboard and autofill, Sharesheet/chooser, file picker grants, cross-profile app links, notifications, overlays and the system home/recents surfaces. Assert policy state and negative crossing with positive controls per direction. A profile badge or copy restriction alone is insufficient. |
| Unauthorized app installation or launch | Require reviewed manifest, package namespace, fresh signed policy, APK hash, signer, version, supported permissions, installed identity and component. Reject tampered binaries, wrong key, old versions, unclaimed and replayed payloads, duplicate/rollback sessions, preinstalled global package collision and external link-based installation. A reviewed install must never replace the parent’s build. Verify Android confirmation behavior and failure paths per image and distribution. |
| Malicious or compromised reviewed app/SDK | Keep arbitrary APKs on dedicated isolated hardware. Constrain app permissions, components, dynamic code, endpoints, storage, process/resources and capability scope. Fixture attempts to call outside its contract, invoke unreviewed components, return oversized/fake/replayed results, retain scheduled work or request delegated privileges. Server and runtime should reject, stop and quarantine. A cooperative app can falsify observations and cannot be the sole test oracle. |
| Egress and exfiltration | Start offline where viable. For networked recipes require profile-scoped default-deny VPN/proxy, TLS, destination allowlist and health signal. Synthetic fixture attempts non-allowlisted host, LAN/loopback targets, DNS and IP forms, IPv6/UDP, redirects, IPC handoff and VPN startup/death. Allowed controlled endpoint succeeds. Local/blocked cases never get an outbound receipt and cause loss of readiness if enforcement fails. Profile-only VPN does not protect personal traffic or prove isolation by itself. |
| Scope escape by agent, reviewer or developer | Treat prompts, app outputs and user reports as untrusted. Perform server and device authorization for every action. Constrain verb/typed inputs, size, rate, deadline, package, observation schema and independently scored state. Reject stale/foreign/forged offers, shell/action injection, capability escalation, out-of-order/duplicate steps, cross-tenant reads and reviewers approving their own evidence. Run existing legacy tenant/lease tests alongside new tests. |
| Screen capture and evidence poisoning | Start with structured schemas. Consent is scoped to target, step, media and recipient. Reject device-wide screenshots, screen text, protected wallet surfaces, notifications and personal windows. Test app switching, secure flags, app-window projection stop, availability of OS indicator and safe owner revocation before considering any screen recording. Never classify an inaccessible/protected screen as verified based on model text. Verify signed manifest and exact content hash, inspect redaction, and flag tampered/stale attachments. |
| Resource abuse, wake, battery and thermal | Require monotonic expiry and bounded action count, duration, storage, bytes, CPU work and job count. Stop on policy thresholds, power/thermal changes, loss of foreground, charging disconnect when required, or unreliable readings past a short age. Test synthetic condition transitions and physical sustained charging/thermal instrumentation. Do not use emulator battery/temperature for policy calibration. Fail closed for unsupported sensor combinations. |
| Owner stop, server revoke and connectivity loss | Immediate owner Stop ends local action authority independent of network. Return through Android UI, profile pause or removal. No lock-task kiosk on personal devices. Runtime refreshes a short TTL and cannot renew locally. Kill requests while offline cannot be promised to arrive. Inject app death, reboot, network loss, server partition, leave foreground, screen lock and competing offers, including while install/launch is pending. Median/tail stop latency and public UI reclaim criteria are set in the acceptance plan. Hold the device in cleanup pending until verified. |
| Cleanup and cross-customer state | Test installed package/UID, local/cache/media data, test wallet identity, jobs/notifications, clipboard, grants, staged installer state, egress state, and backend leases. Seed unique A/B synthetic data and test across successive builds, crashes and reinstall. Include rejected and interrupted work, rollback and emergency stops. Quarantine on residue or no clean acknowledgment. Suppress further matching, record minimal audit and require requalification. Profile removal is owner-approved and removes the entire dedicated test profile. |
| Data reuse and access | Minimize collection, redact before buyer access, hash scope and consent versions, expire links, tenant-check stored objects, audit export and support deletion. Test no training grant, grant withdrawn mid-generation, foreign access, reviewer rejection, expired package, redaction errors and deletion. Document previously delivered copies and contractual retention/deletion. |
| Fraud, signature misuse and duplicate payment | Canonical receipts with algorithm/version and registered key, scoped immutable terms, replay prevention and independent verification of chain effects. Test bogus assertions with valid tester signatures, forged/rotated key, wrong wallet/cluster and concurrent reviewed/payout requests. Persist signatures before broadcast, reconcile exact signed intent and separate accepted work, assertion outcome and payout. |

## Release boundaries

- Consumer scope begins with first-party fixtures, private enrollment, structured evidence, no personal wallet and no paid general assignments. Default to the least capability. Production pilot exposure requires the measured conditions in [implementation and acceptance](implementation.md).
- The system’s managed profile and the app sandbox reduce exposure when policy and supported hardware enforce them. Both depend on the OS. Phases include denial tests, conservative eligibility, no platform hardening claims for rooted or compromised devices, and fail-closed behavior.
- Design server grants so developer actions and full upload tokens are never visible to the person UI. Keep the backend as the authorization authority while the device independently enforces local foreground, scope and expiry.
- Android debug facilities, arbitrary remote ADB/shell, Accessibility for automation, covert recording, bypassing system consent or a protected wallet, device-owner takeover, and personal account inventory are outside the approved phone path.
