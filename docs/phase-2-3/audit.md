# Implementation and adversarial acceptance

Start with the [functionality matrix](functionality-matrix.md), [original matrix](baseline-matrix.md) and [frontend handoff](frontend.md). This is a local preview release package. Personal devices, public funding and deployment remain gated. The [commercial dossier](../research/README.md) supplies buyer context and hypotheses.

## Architecture and release boundaries

The implementation uses three distinct execution classes. The dedicated runner keeps the original protocol and signed evidence. Phone-native execution runs through a separate Work-profile Android preview with a foreground authorization window, separately scoped credentials, server-signed P-256 manifests, profile-owned staged installs and cleanup, and signed scoped observations. The companion retains its existing navigation. Assignment acceptance, technical outcome, evidence provenance and compensation are different records. The preview limits Android execution to the known AOSP image and the pinned permissionless fixture.

P-256 replaced the initial Ed25519 manifest choice after the AVD rejected Ed25519 public-key import through the selected Android provider. Dedicated receipts remain Ed25519. The native preview also requires visible Android confirmations for install and uninstall. Source approval can persist for the app, while its profile policy is restored after staging. Any further reduction in repeated install friction requires review of permitted managed distribution and independent proof of clear-data lifecycle and package collision safety.

## Findings and fixes

| Boundary | Verified evidence and fix | Release limitation |
| --- | --- | --- |
| Runtime grant and credential separation | Person authentication, installation key proof and lease bearer are scoped and distinct. Tests reject credential substitution, enrollment replay and wrong signing keys. | Software self-report is acceptable only for the explicitly enabled local preview. |
| Artifact authority and evidence | Control plane binds signed manifest to installation, attempt and artifact. Download requires the live lease and SHA-256 check. Android validates archive package, certificate, permission/component shape and installed signer. Signed report closes artifact authority while cleanup is pending. | Test wrong publisher, installed version collision and signer replacement across real/OEM images before expansion. |
| Personal data, screen and network | DPC sets sharing and screen-capture restrictions in its own profile. The fixture requests no permissions and returns a fixed vocabulary. Phase 1's canary and direct socket checks are baseline only. | The full cross-profile contact, picker, clipboard, package-update and network-egress suite is still required for a retail phone release. |
| Stop, offline expiry and cleanup | 30 real HTTP cycles used a controlled clock and software P-256 signers. They covered owner stop, expiry, stale proof rejection, denied staging after stop, denied incomplete cleanup and a fresh fenced grant after cleanup. Device code sets local monotonic deadlines and uses a notification watchdog. | Execute actual process-kill, offline and foreground-transition cases with measured owner-reclaim latency on each supported Android image. |
| Tenant, review and concurrency | Actual HTTP and Postgres tests covered immutable revisions, separate participants, one reservation winner, foreign review denial, single earning on duplicate acceptance, restart and campaign-scoped visibility. | Independent deployment database and concurrency target are pending. |
| Wallet ownership and payouts | Actual API signed an exact challenge, rejected wrong key and other owner, rejected replay, and verified replacement and disconnection. Dedicated test-chain path checks finalized chain effects. Settlement Postgres tested uniqueness and compare-and-set across separate pools. | Live MWA ownership approval on the companion and campaign money movement remain gates. |
| Data rights and redaction | Repeated authenticated retrieval enforces two separate grants and current retention and rejects withdrawal or re-grant on an old package. Export projection removes narrative, identifiers and raw screenshots. | The local retention sweeper removes expired detailed submissions, review text and native proof bodies. Hosted backup deletion, delivered copies and hardware trajectory trials require independent verification. |
| UI browser integration | Chromium and actual local services exercised registration, project, browser-computed upload hash, mixed campaign, publish, pause, resume and sign-out. | Test source APK bytes were synthetic. Android lifecycle evidence is separate. |
| Abusive payloads and access | Bounded JSON nesting before idempotency hashing, input/verb bounds, owned record checks and explicit production and non-loopback denial. | The preview HTTP origin is a lab constraint. Production HTTPS and externally authorized secrets are disabled. |

## Run evidence

- [Phase 1 feasibility](https://github.com/omnmlr/agus-ai/actions/runs/45981236275) was the originating baseline.
- [Dedicated Android wallet acceptance](https://github.com/omnmlr/agus-ai/actions/runs/45986849679) passed actual Android with deterministic external control, Localnet positive transaction, false-success negative and reconciliation. Model-driven acceptance [45986172145](https://github.com/omnmlr/agus-ai/actions/runs/45986172145) failed before a model call because the authorized Gemini CI binding was empty.
- [Companion workflow](https://github.com/omnmlr/agus-ai/actions/runs/45988434890) passed the reference APK build. It did not execute the MWA ownership UI journey.
- Native runtime iterations [45986108223](https://github.com/omnmlr/agus-ai/actions/runs/45986108223), [45986980755](https://github.com/omnmlr/agus-ai/actions/runs/45986980755), and [45987987363](https://github.com/omnmlr/agus-ai/actions/runs/45987987363) exercised Android setup, enrollment, install, human test, signed report and cleanup along the path. The first exposed Ed25519 key import, and later runs exposed keyboard navigation in the submission harness. See the continuation checkpoint for current acceptance.
- Local tests used a disposable PostgreSQL 17 container. The earlier external PostgreSQL settlement skip was exercised and passed. No live payments, Mainnet activity or deployment were used.
