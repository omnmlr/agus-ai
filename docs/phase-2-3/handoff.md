## Antigravity assignment

1. Start from the published feature branch and verify the recorded commit and CI artifacts. Preserve your existing Windows/Seeker setup. In a clean checkout, run the `full` and `safety` AOSP journeys. Record the APK SHA-256, signer, manifest key fingerprint, OS and policy. Verify both downloaded receipts with the pinned issuer key and compare the assignment, attempt and build digest with the campaign. ADB bootstraps and observes the lab. Record each interaction and its privilege. [Reproduction and verification commands](../../packages/cooperative-android/README.md)
2. Verify the dedicated lane using an already authorized lab phone/emulator and the existing Localnet tools. Run positive wallet transfer, cancellation, wrong network, and signed-without-broadcast. Capture independent chain evidence with the expected genesis, recipient, amounts and finality. Compare deterministic external actions and signed report verification.
3. For each approved candidate retail OS/OEM, obtain separate owner consent on disposable hardware before attempting enrollment. Use a stock Pixel-class device, one approved high-volume non-Google OEM, and a genuine attended Seeker for hardware claims. Start with an empty personal profile seeded only with synthetic contacts, media, clipboard, test wallets and apps. Validate two directions of bridge attempts, sharing, pickers, protected windows, allowed networking, package collisions and relevant OEM behavior.
4. Run the [Phase 1 acceptance cases](../phase-1/implementation.md) with at least 30 stop/recovery and 30 cleanup trials per qualifying configuration. Include installation interruption, process death, portrait change, network loss, airplane mode, owner Stop, Home, lock, server revocation and reboot. Measure worst local stop/reclaim time and verify no new work until cleanup. Record each trial, artifact, receipt and hardware provenance.
5. On a dedicated controlled device, verify the reference companion points to an authorized control-plane origin. Connect the disposable Fake Wallet, view the exact challenge, decline once, verify once, replace, disconnect, and retry old proofs. Check earnings and ledger behavior. Separately exercise sign-in, native assignment review and consent withdrawal. Never use personal keys or Mainnet.
6. Report reproducible issues with exact image, step, expected and actual result. Record environment classification and untested surfaces. Return only sanitized observations and an independently assessed go/no-go for each lane. A failed safety or evidence gate keeps the affected lane disabled.

## Windows and genuine Seeker verification assignment

Use the exact revision and checksum manifest from the [candidate download](artifact-installation.md). Obtain explicit authorization for each physical phone and use a device with disposable accounts and only synthetic data. Stop before testing if the device is managed by another organization or contains personal keys. [Windows setup](../mobile-test/WINDOWS_PHYSICAL_TESTING.md)

1. Install current Android Platform Tools on Windows. In the approved phone's developer options, enable USB debugging, use a data-capable cable, select the phone in `adb devices -l`, and approve the workstation fingerprint on the unlocked device. If USB still fails, use Wireless debugging on an isolated trusted network. Pair with `adb pair DEVICE_IP:PAIR_PORT`, enter the displayed code, then use `adb connect DEVICE_IP:DEBUG_PORT` and `adb devices -l`. The pairing and debug ports may differ. Use the serial returned by ADB for every command and disable debugging at the end.
2. Check `adb -s SERIAL get-state`, `adb -s SERIAL shell getprop ro.product.model`, `adb -s SERIAL shell getprop ro.build.version.release`, `adb -s SERIAL shell getprop ro.build.version.security_patch`, and `adb -s SERIAL shell pm list users`. Record the OS image, build fingerprints, owner consent and sanitized observations. Report the device brand from trusted device records. A model string alone is insufficient for a genuine Seeker claim.
3. Follow the pinned dedicated runner guide first. Install the checksum-verified companion and ensure the developer’s approved case targets the paired, isolated device only. Before consenting, review the exact package, digest, scenario, capture policy, and stop control. Test denied wallet approval, approved ownership, replacement, disconnect and replay of the old proof. Exercise account-level proof and the explicitly selected device-level row separately. [Dedicated runner](../../services/provider-runner/README.md)
4. On a genuine Seeker, record the Android software release and physical provenance without serial numbers or wallet secrets in the report. Use a disposable test wallet and the approved Devnet endpoint. First use the pinned Fake Wallet control. Then perform a separate interoperability check with the approved Seeker wallet if it supports the exact Devnet test flow. Confirm the expected recipient, amount, genesis, failure or finalized chain effects outside the wallet callback. Record whether Seed Vault was actually exercised. Keep hardware attestation claims disabled unless independently verified.
5. On the reviewed AOSP image, run the Work-profile workflow with the APK and manifest key from the same build. Verify that Android prompts for profile creation, install and removal. Compare `adb -s SERIAL shell pm list packages --user PROFILE_ID` before, during and after the lease. Perform the standalone fixture and independent signer tests, package-collision protection, safe foreground transition, Android notification Stop, server revocation and offline expiry. Use synthetic canaries to check restricted sharing, picks, clipboard and screenshots. Existing profile or unsupported image must block runtime onboarding. The release APK enforces the current AOSP restriction on retail devices.
6. For an independently authorized hardware isolation non-release research build, follow the review in the [Phase 1 safety lab](../phase-1/implementation.md) and record at least 30 stop/recovery and 30 cleanup cycles for each OS/OEM pair. Include interrupted Android install, process kill, reboot, lock, Home, loss of network and repeated disable/enable. Measure worst-case local suspension and owner reclaim. Compare Work and personal profile state after cleanup. Keep the retail gate closed for any missing capability or observation.
7. Record only sanitized results in the acceptance work log. Verify every signed receipt with the trusted issuer key and compare assignment, attempt and APK digest. Remove the disposable Work profile through Android only after the owner confirms it is the correct profile. Remove test packages and wallets, revoke pairing and runtime grants, use `adb disconnect` for Wireless debugging, and confirm the launcher and personal profile are restored.

For sign-in acceptance at the hosted origin, install the authorized companion release APK and run `adb -s SERIAL shell pm verify-app-links --re-verify app.agus.companion` followed by `adb -s SERIAL shell pm get-app-links app.agus.companion`. Confirm `agusai.grindcity.app` is verified. Exercise browser consent, decline, restart during the browser flow, return, retry after cancellation, and logout. Verify a captured disposable callback cannot be exchanged twice. Use the authorized mailbox to validate email delivery and Work-profile sign-in for the same Google-created account. The companion and Work profile have separate sessions.
