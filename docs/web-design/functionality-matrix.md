# Developer console functionality

Paths below use the same-origin `/api/v1` prefix. The server determines tenant ownership and deployment eligibility. Consult the [OpenAPI schema](../../packages/developer-client/openapi.json) and [frontend contract](../../FRONTEND_CONTRACT.md) for request and state semantics.

| Console area | Working actions | API contracts and verification |
| --- | --- | --- |
| Sign-in | Password, optional registration token, email code, Google PKCE, session refresh and logout | `/auth/register`, `/auth/login`, `/auth/email/{start,verify}`, `/auth/google/{start,callback,exchange}`, `/auth/{refresh,logout}`. Browser exercised invited password registration, tab persistence, rotation, logout and unavailable Google. Existing API tests exercised configured identity flows using isolated provider fixtures. |
| Overview and builds | List/create projects and register exact APKs with browser hashing and server validation | `GET/POST /projects`, `GET/POST /builds`. Disposable browser uploaded fixture APK bytes, and the Neon smoke uploaded an 80 KB fixture. Device-side build approval is separate. |
| Test runs | Create, filter, monitor or cancel; view run, execution, lease, stop and evaluation states | `GET/POST /runs`, `GET /runs/{id}`, `GET /runs/{id}/events`, `POST /runs/{id}/cancel`. Browser exercised creation, filters, persisted cancellation and foreign-account denial. |
| Agent evaluation | Display recorded agent actions, signed planner/model metadata when present, and comparable runs | `GET /runs/{id}/actions`, `GET /runs/{id}`. Corrections use an eligible reference run in a campaign; eligible running agent executions can queue describe, a runner-returned semantic tap, or finish. |
| Private access and devices | View eligible devices, share requests, review invitation terms, accept, decline, revoke | `GET /devices`, `GET/POST /invitations`, plus supported invitation operations. Device pairing and management are managed in the companion. Routing, scoped access, and exact build acceptance covered by API and web checks. |
| Campaigns | Draft and revise, configure lanes, coverage, instructions, constraints, fixed outcome rubric, budget, retention and invitations; publish, pause, resume, complete and cancel | `GET/POST /campaigns`, `PATCH /campaigns/{id}`, and `POST /campaigns/{id}/{launch,pause,resume,complete,cancel}`. Browser exercised mixed-lane drafting, publication, pause and resume. |
| Findings and evidence | Review submissions by attempt and version, request revision, accept or reject where available, download receipt or permitted attachment, retry independent verification | `GET /campaigns/{id}/report`, `POST /assignments/{id}/reviews`, `GET /assignments/{id}/receipt`, `GET /runs/{id}/evidence/{sha256}`, `POST /runs/{id}/verify`. Browser accepted a fixture submission and independently verified its downloaded receipt. |
| Settlement | View, quote, download, and verify funding; display test-unit or chain terms; reconcile eligible payouts and refunds | `/campaigns/{id}/funding` and `/{quote,verify,refund}`, `/assignments/{id}/payment`, `/runs/{id}/{payment,quote,funding,settle,reconcile}`. Browser exercised unpaid terms and a Localnet quote with an injected test chain that rejected unconfirmed funding. |
| Training rights | Grant or withdraw developer consent for eligible assignments and dedicated run trajectories, and download redacted exports | `PUT/DELETE /me/assignments/{id}/training-consent`, `POST /campaigns/{id}/exports`, `GET /campaigns/{id}/exports/{id}`. API fixture verifies two-party grants and withdrawal. |
| Settings and inbox | Update display name, optional inbox categories and notification read state | `GET/PATCH /auth/me`, `GET/PATCH /me/notifications/preferences`, `GET /me/notifications`, `POST /me/notifications/{id}/read`. Browser exercised profile and preference writes. |
| Integrations | View and copy versioned examples for the HTTP API, SDK, CLI and MCP | [Public guides](../../apps/web/scripts/content.mjs) draw on the checked-in client and OpenAPI. SAS issuance and verification remain operator and CLI workflows. |

Creation retries for runs, campaign drafts and invitations reuse a request key for an identical retry in the current tab when the result is ambiguous. The console asks the developer to check the resource list before retrying.
